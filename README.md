# Qwen-Image 2.1 on AMD Radeon GPUs

**Native Windows ROCm · Reproducible image generation · AMD Radeon RX 7900 XTX 24 GB**

Run Alibaba's Qwen-Image-2.1 locally on a 24 GB Radeon card under
native Windows ROCm — with a one-command quickstart, frozen benchmark
protocol, quality-gated optimizations, and public evidence for every
number on this page.

| Verified on this exact stack | Number | What it means (and what it doesn't) |
|---|---|---|
| **1024² generation, Fast mode** | **~9 s / image (warm)** | Same prompt, models resident, text-encoder cached. Full cold start 50.8 s (E8 default, measured), changed prompt ≈ +3–7 s (bf16 TE) → [real-world latency](docs/benchmarks/REAL_WORLD_LATENCY.md) |
| **Speedup vs bf16-40 baseline** | **5.2–5.5× (warm, paired)** | Same-session measured pair; images differ (8-step turbo) — quality judged by humans on the frozen grid, not assumed lossless |
| **2048² native resolution** | **40.2–40.4 s / image** | Bounded matrix measured: 3 prompts × 3 seeds, spread 0.5%, first-ever 2048² typography runs — soak/OOM-recovery not claimed — [details](docs/benchmarks/2048_VALIDATION.md) |
| Tested GPU / OS | RX 7900 XTX (gfx1100) · Windows 11 | Native Windows ROCm — no WSL2, no CPU fallback. Other GPUs untested (fail-closed by default) |
| ROCm stack | torch 2.12.0+rocm7.14.1 · ComfyUI pinned | Pinned AMD wheels, pinned ComfyUI commit, schema-validated run records |

*Every claim above resolves to a committed run record — see the
[claim → evidence matrix](docs/benchmarks/CLAIM_EVIDENCE_MATRIX.md).*

## Quick start

Prerequisites: Windows 11, Radeon RX 7900 XTX, current Adrenalin driver,
[uv](https://docs.astral.sh/uv/), git, ~26 GB disk for Fast weights.

```powershell
git clone https://github.com/AIwork4me/qwen-image-rocm.git
cd qwen-image-rocm
.\quickstart.ps1 -Mode Fast        # first image in minutes; ~8-9 s/image warm
.\quickstart.ps1 -Mode Quality     # bf16 40-step, bit-identical baseline
.\quickstart.ps1 -Mode Fast -Resolution 2048
```

One command runs the whole chain: OS/GPU/gfx1100 checks → isolated venv with
pinned AMD ROCm wheels → ComfyUI at the pinned commit (a mismatched commit
fails closed) → weight integrity via pinned-revision SHA256 for **every**
file (upstream revision `aacf31a6`, digests embedded in-repo; resumable
downloads) → server health gate that **requires a Radeon
device** (no silent CPU fallback) → generation via the same driver as the
benchmarks → printed `Server boot / Ready-to-first-image / Full cold start /
Warm mean+median`. First-ever run downloads weights once; after that, full
cold start is ~51 s on the E8 default (bf16 text encoder; measured).

Phase-1 diffusers reproduction stays available: `.\reproduce.ps1 -Quick`.

## Fast vs Quality

| | Fast | Quality |
|---|---|---|
| Config | Turbo 8-step · int8 DiT + **bf16 TE** · `--use-ck-attention` (E8, owner-approved) | bf16 40-step · `--disable-smart-memory` |
| 1024² warm | ~9 s | ~45–51 s |
| 2048² | ✅ 40.2–40.4 s (bounded matrix, n=9) | ❌ (bf16 VAE decode OOMs on 24 GB) |
| Output vs baseline | different (8-step schedule), **judged 无感 on the frozen grid (A1 + #5)**. An int8-TE variant (the "production triple", slightly faster) was **rejected by the owner verdict** — p1 略降, p3 typography 不可接受 ([#5](https://github.com/AIwork4me/qwen-image-rocm/issues/5)); LPIPS did not predict the p3 call — human gate is binding | **bit-identical** (LPIPS 0.0000) |
| Weights on disk | ~26 GB | ~32 GB |

Both profiles are frozen experiment manifests
([bench/quickstart_config.py](bench/quickstart_config.py)) — the quickstart
cannot drift from what was measured. How quality is judged:
[QUALITY_METHODOLOGY.md](docs/benchmarks/QUALITY_METHODOLOGY.md).

## Real-world latency (Fast = E8 default, 1024²)

Unified vocabulary — defined precisely in
[REAL_WORLD_LATENCY.md](docs/benchmarks/REAL_WORLD_LATENCY.md). Fast ships
the E8 config (bf16 TE), so its cold path includes a 17.5 GB text-encoder
load + ~7 s cold encode:

| Metric | Fast (E8, default — measured 2026-11-01) |
|---|---|
| Server boot | 18.2 s |
| Ready-to-first-image | 32.6 s (cold TE 7.16 s incl.) |
| **Full cold start** (launch → 1st PNG) | **50.8 s** |
| Fresh prompt (text changed) | warm + 3–7 s (bf16 TE, phase-3 measured) |
| Warm repeat (new seed) | mean 9.18 s / median 9.07 s |
| 2048² Fast warm | 42.2 s (turbo-int8 probe, same bf16-TE family) |

For reference, the rejected int8-TE triple variant was faster to cold
(full cold 20–46 s, warm 8.0–9.2 s, fresh ~10 s) — see
[REAL_WORLD_LATENCY.md](docs/benchmarks/REAL_WORLD_LATENCY.md). Quality
(bf16-40): full cold start 67.5 s, warm ~46 s. Rebooted-machine cold start
**not tested**; VRAM figures are 0.5 s samples (lower bounds).

## Reproduce the benchmarks

```powershell
# protocol-grade (fresh server per variant, 3 prompts × 3 seeds, quality gates):
powershell -File bench\run_variant.ps1 -Experiment p3-turbo-int8-ck-te-nosmart-1024x1024 -Date mydate
# Phase-1 diffusers baseline:
.\reproduce.ps1 -Full
```

Frozen protocol: 3 prompts (zh scene / en scene / zh typography poster) ×
seeds [42, 1337, 20261030], euler/simple, cfg 1.0, cold+warmup+measured
discipline with cache-defeating seeds
([bench/prompts.json](bench/prompts.json),
[schema](bench/schema/result.schema.json)). Historical results are
read-only; corrections land as new runs + errata, never as edits.

Key results (medians of measured runs; full tables in
[phase-3 summary](bench/results/2026-11-01-phase3-summary/report.md)):

| Lever (1024², warm) | total s | vs paired bf16 control | quality |
|---|---|---|---|
| Turbo-int8 + ck (e8) | 9.1 | 5.2–5.5× | distance 0.21–0.36 → user verdict: indistinguishable |
| **Fast = Turbo-int8 + ck (E8, shipped default)** | **9.1** | 5.2–5.5× | judged 无感 (A1 + #5) |
| int8-TE "triple" variant (r1) — **rejected as default by #5** | 8.0–9.2 | ~5.5–6.0× cross-session* | verdict: p1 略降, p3 不可接受 (LPIPS vs e8 0.058/0.012/0.014 did not predict it) |
| ck attention alone (40-step) | 35–37 | 1.30–1.37× | different numerics path → grid verdict |
| int8 DiT / TE (40-step) | 45–50 | ~1.0× | near-lossless 0.004–0.060 |
| `--disable-smart-memory` | 42–46 | 1.06–1.14× | bit-identical |
| `--highvram`, `--fast fp16_accumulation` | 163/224 | 0.2–0.3× | rejected with data |
| diffusers + cpu_offload baseline | 239–254 | — | Phase 1 |

\* cross-session context only; the same-session paired claim is the e8 row.

## Architecture & optimizations

- **Why ComfyUI is 5× diffusers here**: diffusers pays ~90 s/run of
  cpu_offload PCIe shuffling (31 GB) + 3.66 s/step; ComfyUI keeps the DiT
  resident. Details: [Phase 2 report](bench/results/2026-10-31-comfyui-1024/report.md).
- **The int8 unlock**: native `.comfy_quant` checkpoints auto-load via plain
  loaders (no custom nodes) — half the weights, speed parity at 1024²,
  and the only route that fits 2048² attention + weights in 24 GB.
- **Measurement infra (protocol v1.3)**: websocket node/step timing
  (text-encode / denoise / VAE split), node-cache hit accounting, sampled
  VRAM peaks, per-variant server lifecycle with attention-path evidence
  scraped from server logs ([bench/comfyui_client.py](bench/comfyui_client.py)).

## Known limitations

- Warm numbers ≠ user latency (cold/fresh/warm are separated
  [here](docs/benchmarks/REAL_WORLD_LATENCY.md)).
- 2048² is validated to bounded-matrix depth (13 consecutive generations);
  soak/OOM-recovery untested
  ([ledger](docs/benchmarks/2048_VALIDATION.md)).
- VRAM figures are 0.5 s samples — lower bounds on transients.
- Quality verdicts describe the frozen 3-prompt × 3-seed set, nothing wider.
- torch.compile/FlexAttention blocked: no Triton wheels for Windows ROCm.

## ROCm-on-Windows findings & upstream contributions

Real-workload RCA with minimal reproducers — all posted upstream
2026-11-01 ([index](docs/upstream/INDEX.md)):

1. flash/mem-efficient SDPA `hipErrorInvalidValue` from S=64 on
   torch 2.12.0+rocm7.14.1 Windows — root-caused to an AOTriton
   runtime/images mismatch in the wheel (TheRock#7315/#7992); verified
   locally with a weights-free 192-cell repro; 7.14.0 from the same index
   is clean and 3.4× faster (flash) — stack-switch is a documented user
   choice, repo default stays 7.14.1 + `QIR_SDP=math` workaround.
   [TheRock#7315 comment](https://github.com/ROCm/TheRock/issues/7315#issuecomment-6554228687) ·
   [transformers#50211](https://github.com/huggingface/transformers/issues/50211)
2. No Triton wheels for Windows ROCm (verified distribution gap; TheRock
   PR#4006 merged but unpublished) →
   [issue doc](docs/issues/2026-10-30-no-triton-windows-rocm.md)
3. cpu_offload first-warmup pagefile thrash on 32 GB-RAM hosts →
   [accelerate#4488](https://github.com/huggingface/accelerate/issues/4488)
4. Resilience asymmetry: ComfyUI survives the broken SDPA kernels via a
   startup probe and falls back; diffusers/transformers fail the whole call —
   probe-pattern proposal posted to transformers#50211.
5. hf_transfer/hub resume behavior on flaky mirrors →
   [huggingface_hub#4196 comment](https://github.com/huggingface/huggingface_hub/issues/4196#issuecomment-6554229435)
6. RDNA3-Windows attention-backend perf data: `--use-ck-attention`
   1.30–1.37× →
   [comfy-kitchen#292](https://github.com/Comfy-Org/comfy-kitchen/issues/292);
   VAEDecodeTiled and fp16_accumulation regressions →
   [ComfyUI#17469](https://github.com/Comfy-Org/ComfyUI/issues/17469) ·
   [ComfyUI#17470](https://github.com/Comfy-Org/ComfyUI/issues/17470)
